type=1 为入向（用户提示词进入模型前的检测）， type=2 为出向（模型响应返回用户前的检测）。 该字段未见于官方字段文档，语义由使用方确认。数据与之相符：提示词注入落在入向， 涉政内容与 IP / URL 外泄落在出向。
两个方向的 content 粒度完全不同：入向是整段提示词一次送检（中位 9950 字符， 多数撞上 10 KiB 上限）；出向是边流式输出边逐块扫描，一条记录只装一个分片 （中位 55 字符、最长 136），首尾常断在词或 URL 中间。出向内容看着不完整是分片边界， 不是被截断。 type=1 is inbound (checked before the prompt reaches the model); type=2 is outbound (checked before the response reaches the user). The field is absent from the public field docs — semantics confirmed by the operator. The data agrees: prompt injection is inbound; political content and IP / URL leakage are outbound.

正文里出现这个词就不推，不分大小写，不是全等也不需要通配符（写 * 会被忽略）。 同时也看检出摘要 attack_content，因为正文撞上 10 KiB 上限时关键词可能只剩在摘要里。
用来挡「正文里带了某个特定东西」的误报，例如 doubao-seedance：生视频接口回吐的预签名地址 query 里带 X-Tos-Credential=AKLT…，被 gdl-019 当成 AccessKey 泄露报出来， 而按规则 ID 加白会连真的 AK 泄露一起放过。
代价是这个词成了免推口令：只要正文里出现它，同一条记录里别的问题也一起不推了，所以别用太常见的词。 Suppresses a push when the body contains the word (case-insensitive substring — no wildcard needed; a * is ignored). attack_content is searched too, since the body may be cut at 10 KiB.
For false positives tied to a specific string, e.g. doubao-seedance: the presigned video URL carries X-Tos-Credential=AKLT… and trips gdl-019 as an AccessKey leak, whereas allowlisting that rule would also let real AK leaks through.
The cost is that the word becomes a mute token — anything else wrong in the same record is silenced with it, so avoid common words.
有些记录不含 chat_id，无从知道是谁触发 —— 主要是 2026-08-13 16:53 之前的 ToolCall 记录（那之后这条路径开始返回 chat_id 了）， 另有少量旧格式 chat_id 拆不出用户。打开后这些一律不再推送 —— 注意其中包含已拦截和高危记录，等于把最该看的一批也一起静音了，只适合临时用。 Some records carry no chat_id and cannot be attributed — mostly ToolCall records from before 2026-08-13 16:53 (the path started returning chat_id after that), plus a few legacy chat_id values with no user name. 部署到另一台服务器Deploying elsewhere

只依赖 Python 3.8+ 标准库，没有第三方包 Python 3.8+ standard library only, no third-party packages
  1. 把整个目录拷过去。不要带 config.json 和 webhook_state.json —— 前者含密钥，后者是本机的「已推送」记录，带过去会让新机器漏推那批告警。 Copy the whole directory. Leave out config.json and webhook_state.json — the first holds credentials, the second is this host's push history and would make the new host skip those alerts.
  2. 起服务：python serve_dashboard.py。不带任何环境变量也能起来。 Start it: python serve_dashboard.py. It boots with no environment variables set.
  3. 打开页面回到本页签，填密钥与 webhook，点「测试连通」确认，再保存。 Open the page, come back to this tab, fill in the credentials and webhook, hit Test, then save.
  4. 要让密钥不落盘，改设环境变量 TENCENTCLOUD_SECRET_ID / TENCENTCLOUD_SECRET_KEY / FEISHU_WEBHOOK_URL；它们优先级高于配置文件，本页对应输入框会自动置灰。 To keep secrets off disk, set TENCENTCLOUD_SECRET_ID / TENCENTCLOUD_SECRET_KEY / FEISHU_WEBHOOK_URL instead — they outrank the config file and the fields above grey out.
  5. 要监听到其他网卡，加 --host 0.0.0.0 --admin-token <令牌>。不给令牌时写配置的接口会自动禁用：本服务没有账号体系，而日志正文含内网地址与凭证形态内容。放到内网也建议前面挡一层反向代理做认证。 To listen on another interface use --host 0.0.0.0 --admin-token <token>. Without a token the write endpoints are disabled — this service has no account system and the log bodies contain internal addresses. Put an authenticating reverse proxy in front.
配置文件位置 —，保存时会尽量把权限收到「仅当前用户可读」。这不是加密，只是别让同机其他账户随手读走。 Config file: —. Saving tightens permissions to the current user where the OS allows. That is not encryption — only a guard against other local accounts.
